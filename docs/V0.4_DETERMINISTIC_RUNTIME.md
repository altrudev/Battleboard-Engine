# Battleboard Engine v0.4 — Deterministic Runtime

## Purpose

v0.4 makes Battleboard's tactical state reproducible, inspectable and safe to simulate without requiring the 3D presentation layer. It is intentionally compatible with the current Battleboard-Game demo while providing a migration path to a single authoritative match simulation.

## Compatibility

Existing game calls remain valid:

- `BBBoardState.new()` and the existing occupancy/role/side dictionaries remain available.
- `BBBoardState.move_profile(profile_id, destination)` remains available and is now transactional.
- `BBBoardRules.legal_moves(state, profile_id)` is unchanged.
- `BBAffinityEngine.evaluate(a, b)` is unchanged.
- `BBTacticalPlanner.choose_move(state, profiles, side)` remains valid; v0.4 adds optional search depth and beam width parameters.
- `BBPieceVisual.configure(profile, side, role)` remains valid; a production scene is optional.

## New authoritative path

New match logic should use:

1. Build a `BBBoardState` and profile dictionary.
2. Create `BBMatchSimulation` and call `setup(state, profiles, seed)`.
3. Submit only `BBMatchCommand` dictionaries to `apply_command()`.
4. Drive presentation from returned `BBMatchEvent` rows.
5. Persist the initial snapshot, seed and commands in `BBReplay` when replay evidence is required.

The game can continue to use direct-control encounters. `BBMatchSimulation` is the deterministic tactical authority; `BBEncounterContext` remains the handoff boundary for player-controlled challenge presentation.

## Production characters

`BBPieceVisual` keeps the procedural fighter as a guaranteed fallback. A fighter can opt into an imported production character by adding a resource path to profile metadata:

```json
{
  "metadata": {
    "visual_scene": "res://characters/hana/hana.tscn"
  }
}
```

The production scene may contain `Skeleton3D`, `AnimationTree` or `AnimationPlayer`. Conventional child names `equipment_socket`, `weapon_socket`, `hand_r_socket`, `label_anchor`, `head_anchor`, or `ui_anchor` are discovered automatically.

## Determinism contract

Given the same:

- initial board snapshot;
- fighter profile data;
- command sequence;
- RNG seed;
- Battleboard Engine version;

the runtime must reproduce the same event order and simulation hashes. A changed hash is evidence of a behavioral change and should be reviewed before an engine upgrade is promoted.

## Validation

Run against the pinned Godot 4.7.1 editor/runtime:

```bash
godot --headless --path . --script tests/runtime_smoke.gd
```

The smoke suite covers transactional captures, board invariants, seeded engagement repeatability, replay hash verification, deterministic ability/status resolution, planner repeatability and legacy-compatible profile schema migration.

No GitHub Actions workflow is required. This command can be executed locally or by a controlled DDC/Calibration runner.
